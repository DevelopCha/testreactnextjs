## 1. Middleware의 정체

### 1.1 별도 라이브러리가 아니다

**결론: Next.js 프레임워크의 내장 기능**

```typescript
// middleware.ts
import { NextResponse } from 'next/server';  // Next.js 내장 모듈
import type { NextRequest } from 'next/server';

export function middleware(request: NextRequest) {
    // 이 함수가 모든 요청의 "중간"에서 실행됨
    return NextResponse.next();
}
```

**특징:**
- ❌ 별도 라이브러리 설치 필요 없음
- ❌ 외부 소프트웨어 아님
- ✅ Next.js 프레임워크의 **내장 기능**
- ✅ 파일 이름(`middleware.ts`)과 위치만 맞추면 자동 실행

### 1.2 파일 위치

```
프로젝트 루트/
├── middleware.ts          ✅ 여기 (우선순위 1)
└── src/
    └── middleware.ts      ✅ 또는 여기 (우선순위 2)
```

### 1.3 "미들웨어"의 의미

**Middle(중간) + Ware(소프트웨어) = 중간에서 실행되는 소프트웨어**

```
클라이언트 요청
    ↓
[Middleware] ← 🎯 여기서 뭔가 처리 (로깅, 인증 등)
    ↓
실제 비즈니스 로직 (라우트 핸들러)
    ↓
응답
```

## 2. Router vs Middleware

### 2.1 핵심 차이점

| 항목 | Router (라우터) | Middleware (미들웨어) |
|------|----------------|---------------------|
| **역할** | URL → 페이지 매칭 | 요청 가로채기/검사 |
| **실행 시점** | 요청 처리 중 | **라우터 실행 전** |
| **목적** | 어디로 갈지 결정 | 갈 수 있는지 확인 |
| **비유** | 주소 찾기 | 경비실 검문 |
| **Next.js** | 파일 기반 라우팅 | `middleware.ts` |
| **예시** | `/mypage` → `pages/mypage.tsx` | 인증 체크, 리다이렉트 |

### 2.2 Router (라우터)

**역할:** URL을 보고 **어느 페이지를 보여줄지 결정**

```typescript
// Next.js의 파일 기반 라우팅
pages/
  ├── index.tsx           → /
  ├── about.tsx           → /about
  └── mypage.tsx          → /mypage

// 라우터가 하는 일:
// "/mypage" 요청 → mypage.tsx 파일 실행
```

**비유:**
```
우체부가 주소를 보고 집을 찾는 것
"/mypage" → "mypage.tsx 집으로 가자"
```

### 2.3 Middleware (미들웨어)

**역할:** 라우터가 작동하기 **전에** 요청을 가로채서 **검사/수정/차단**

```typescript
// middleware.ts
export function middleware(request: NextRequest) {
    // 라우터 실행 전에 먼저 체크
    if (!request.cookies.get('auth')) {
        return NextResponse.redirect('/login');  // 라우터까지 안 감
    }
    return NextResponse.next();  // 라우터로 보냄
}
```

**비유:**
```
우체부가 집에 가기 전에 경비실에서 신분 확인
경비: "출입증 있어요?" 
  → 없으면: "로비로 가세요" (집까지 안 감)
  → 있으면: "통과" (우체부가 집으로 감)
```

## 3. 실행 순서

### 3.1 전체 플로우

```
사용자 요청: GET /mypage
    ↓
┌─────────────────────────────────┐
│  1. Middleware (있다면)          │  ← 🚦 검문소
│     - 인증 체크                   │
│     - 권한 확인                   │
│     - 리다이렉트 결정              │
└─────────────────────────────────┘
    ↓
    ├─ NextResponse.redirect('/login') → 여기서 끝 (라우터 안 감)
    └─ NextResponse.next() → 아래로 진행
    ↓
┌─────────────────────────────────┐
│  2. Router                       │  ← 🗺️ 주소 찾기
│     - URL 매칭                    │
│     - 파일 찾기                   │
│     - pages/mypage.tsx 실행       │
└─────────────────────────────────┘
    ↓
┌─────────────────────────────────┐
│  3. Page Component               │  ← 🏠 최종 목적지
│     - mypage.tsx 렌더링           │
│     - HTML 생성                   │
└─────────────────────────────────┘
    ↓
응답 전송
```

### 3.2 구체적인 예시

#### ❌ Middleware 없이 (Router만)

```typescript
// pages/mypage.tsx
export default function MyPage() {
    // 🔴 문제: 이미 페이지가 렌더링되고 있음
    const router = useRouter();
    
    useEffect(() => {
        if (!isLoggedIn()) {
            router.push('/login');  // 깜빡임 발생
        }
    }, []);
    
    return <div>My Page</div>;  // 잠깐 보임
}
```

**흐름:**
```
1. Router: "/mypage" → mypage.tsx 실행
2. 페이지 렌더링 시작
3. useEffect 실행 → "앗, 로그인 안 했네?"
4. 리다이렉트 → 깜빡임 발생
```

#### ✅ Middleware + Router

```typescript
// middleware.ts
export function middleware(request: NextRequest) {
    if (!request.cookies.get('auth')) {
        return NextResponse.redirect('/login');  // 여기서 차단
    }
    return NextResponse.next();
}

// pages/mypage.tsx
export default function MyPage() {
    // ✅ 여기까지 왔다 = 이미 인증됨
    return <div>My Page</div>;  // 안전하게 렌더링
}
```

**흐름:**
```
1. Middleware: "로그인 했어?" → 없으면 /login으로 (끝)
2. Middleware: "통과" → Router로 진행
3. Router: "/mypage" → mypage.tsx 실행
4. 페이지 렌더링 (깜빡임 없음)
```

```
프로젝트 루트/

    └── middleware.ts      ✅ 또는 여기 (우선순위 2)
```

### 4.2 방법 2: 브라우저 개발자 도구

```
1. 페이지 접근 (예: /mypage)
   ↓
2. F12 → Network 탭
   ↓
3. 요청 확인
   ↓
4. 리다이렉트 발생했나?
   - Status: 307 (Temporary Redirect)
   - Location: /verify?redirect=/mypage
   ↓
5. 리다이렉트 있으면 → Middleware 있음
```

**확인 예시:**
```
Request URL: http://localhost:3000/mypage
Status Code: 307 Temporary Redirect  ← 🎯 Middleware가 리다이렉트함
Location: /verify?redirect=/mypage
```

## 5. 미들웨어 수정 가이드

### 5.1 수정해도 되는 경우

#### ✅ 개인 프로젝트 / 학습 프로젝트
```typescript
// ✅ 자유롭게 수정 가능
export function middleware(request: NextRequest) {
    // 내 페이지 추가
    if (request.nextUrl.pathname === '/my-new-page') {
        // 내 로직 추가
    }
}
```

#### ✅ 명확한 요구사항이 있는 경우
```typescript
// ✅ 예: "관리자 페이지 보호 추가해주세요"
export function middleware(request: NextRequest) {
    // 기존 로직
    if (isProtectedPath(pathname)) {
        // ...
    }
    
    // ✅ 새로운 요구사항 추가
    if (pathname.startsWith('/admin')) {
        if (!isAdmin(request)) {
            return NextResponse.redirect('/403');
        }
    }
}
```

#### ✅ 설정 파일을 통한 간접 수정 (권장)
```typescript
// middleware.ts (수정 안 함)
export function middleware(request: NextRequest) {
    if (isProtectedPath(pathname)) {  // 설정 파일 참조
        // ...
    }
}

// ✅ password-config.ts (여기만 수정)
export const PROTECTED_PATHS = [
    '/mypage',
    '/my-new-page',  // ✅ 추가
];
```

### 5.2 수정하면 안 되는 경우

#### ❌ 회사 프로젝트 (팀 작업)
```
❌ 혼자 수정하면 안 됨
  ↓
1. 팀장/시니어에게 문의
2. 코드 리뷰 요청
3. 승인 후 수정
```

**이유:**
- Middleware는 **모든 요청**에 영향
- 다른 팀원의 코드에 영향 가능
- 보안 정책과 연관될 수 있음

#### ❌ 보안 관련 로직이 있는 경우
```typescript
// ❌ 함부로 수정하면 보안 구멍
export function middleware(request: NextRequest) {
    // 인증 체크
    if (!verifyToken(request)) {
        return NextResponse.redirect('/login');
    }
    
    // 권한 체크
    if (isAdminPath(pathname) && !isAdmin(request)) {
        return NextResponse.redirect('/403');
    }
}
```

**수정 전 확인:**
- 이 로직을 왜 만들었는지
- 수정하면 보안에 영향 없는지
- 다른 페이지에 영향 없는지

#### ❌ 잘 모르는 로직이 있는 경우
```typescript
// ❌ 이게 뭔지 모르겠다면 수정 금지
export function middleware(request: NextRequest) {
    // 이게 뭐하는 코드지...?
    const token = request.headers.get('x-custom-token');
    if (token && validateComplexLogic(token)) {
        // ???
    }
}
```

## 6. 실무 체크리스트

### 6.1 Middleware 수정 전 체크리스트

```
□ 1. Middleware가 왜 존재하는지 이해했는가?
□ 2. 내 수정이 다른 페이지에 영향 없는가?
□ 3. 보안 정책을 위반하지 않는가?
□ 4. 팀원에게 확인했는가? (팀 프로젝트)
□ 5. 테스트 계획이 있는가?
□ 6. 롤백 방법을 알고 있는가?
```

### 6.2 안전한 수정 방법

#### Step 1: 현재 로직 이해
```typescript
// middleware.ts 읽기
export function middleware(request: NextRequest) {
    const { pathname } = request.nextUrl;
    
    // 🔍 이해하기:
    // 1. 어떤 경로를 체크하나?
    // 2. 어떤 조건으로 차단하나?
    // 3. 차단 시 어디로 보내나?
}
```

#### Step 2: 영향 범위 파악
```typescript
// config.matcher 확인
export const config = {
    matcher: [
        '/((?!api|_next/static|_next/image|favicon.ico).*)',
        // 🔍 어떤 경로에서 실행되나?
    ],
};
```

#### Step 3: 설정 파일 우선 수정 (권장)
```typescript
// ✅ 먼저 설정 파일 수정 시도
// password-config.ts
export const PROTECTED_PATHS = [
    '/mypage',
    '/my-new-page',  // 추가
];

// middleware.ts는 수정 안 함
```

#### Step 4: 테스트
```bash
# 1. 내 페이지 테스트
http://localhost:3000/my-new-page

# 2. 기존 페이지 영향 확인
http://localhost:3000/mypage
http://localhost:3000/order/history

# 3. 공개 페이지 정상 작동 확인
```

#### Step 5: Git으로 안전하게 작업
```bash

git checkout -b feature/add-protected-page

# 2. 수정
```

## 7. 다른 프레임워크와 비교

### 7.1 Express.js (Node.js)
```javascript
const express = require('express');
const app = express();

// 🚦 Middleware
app.use((req, res, next) => {
    console.log('요청 받음');
    next();  // 다음으로
});

// 🗺️ Router
app.get('/mypage', (req, res) => {
    res.send('My Page');
});
```

### 7.2 Django (Python)
```python
# 🚦 Middleware
MIDDLEWARE = [
    'django.middleware.security.SecurityMiddleware',
    'django.middleware.common.CommonMiddleware',
]

# 🗺️ Router (URL 패턴)
urlpatterns = [
    path('mypage/', views.mypage),
]
```

### 7.3 Spring Boot (Java)
```java
// 🚦 Middleware (Filter/Interceptor)
@Component
public class AuthFilter implements Filter {
    public void doFilter(request, response, chain) {
        // 인증 체크
        chain.doFilter(request, response);
    }
}

// 🗺️ Router (Controller)
@GetMapping("/mypage")
public String mypage() {
    return "mypage";
}
```

**모든 프레임워크가 Router와 Middleware를 구분합니다!**

## 8. 핵심 정리

### 8.1 Middleware의 정체

```
✅ Next.js 프레임워크의 내장 기능
✅ 별도 라이브러리 설치 불필요
✅ middleware.ts 파일만 생성하면 자동 실행
✅ "요청 가로채기 함수"
```

### 8.2 Router vs Middleware

```
Router (라우터)
  - URL → 페이지 매칭
  - "어디로 갈지" 결정
  - 비유: 주소 찾기

Middleware (미들웨어)
  - 요청 가로채기/검사
  - "갈 수 있는지" 확인
  - 비유: 경비실 검문
  - Router 실행 전에 먼저 실행
```

### 8.3 수정 가능 여부

```
✅ 개인/학습 프로젝트: 자유롭게 수정
⚠️ 팀 프로젝트: 팀장/시니어 확인 후
❌ 보안 로직: 함부로 수정 금지

권장: 설정 파일 우선 수정 (middleware.ts는 최소화)
```

## 9. 최종 비유

```
🏢 회사 건물

[경비실] ← 🚦 Middleware
  ↓
  ├─ 출입증 없음 → 로비로 안내 (Router까지 안 감)
  └─ 출입증 있음 → 통과
  ↓
[안내 데스크] ← 🗺️ Router
  ↓
  "3층 회의실로 가세요" (URL → 페이지 매칭)
  ↓
[회의실] ← 🏠 Page Component
```
